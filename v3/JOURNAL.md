## Архитектура v3 (кто что делает)

**Правило №1: каждый тянет монитор ТОЛЬКО НА СЕБЯ. Правило №2: DDC-мастер — только mini.**

- **mini, `~/bin/kvm-follow.sh`** (launchd `com.kvm.follow`): опрос `blueutil --is-connected "MX Keys Mini"` (по ИМЕНИ! по MAC врёт) каждые 0.3 с.
  - Клавиатура ушла → тройная посылка `m1ddc set input-alt 465` + досылки на +3 и +6.5 с (probe-guarded) + SSH-побудка макбука (ретраи, отменяемая) + пуш мыши через fifo.
  - Клавиатура пришла → тройная посылка `input-alt 144`.
  - Конвергенция мыши: клавиатуры нет + мышь ещё на mini (blueutil) → пуш, раз в 8 с.
  - Спасение: макбук молчит по SSH после 4 ретраев → монитор возвращается на mini (лучше, чем вечный чёрный экран).
- **макбук, `~/bin/kvm-mb-agent.py`** (launchd `com.kvm.mb`, python+ctypes+libhidapi brew): слушает Bolt (нотификации 0x41/0x40, включаются reg 0x00←00 01 00; карта слотов — fake arrival reg 0x02←02).
  - Клавиатура пришла → **цикл повторных побудок** `caffeinate -u -t 5` каждые 2.5 с × 6 (см. «Гонка гашения») + удержание дисплея `caffeinate -d -w <pid агента>` (только на AC). **DDC не трогает.**
  - Клавиатура ушла → HID++ 0x1814 SetCurrentHost(1) мыши через ресивер → снять удержание → `pmset displaysleepnow` (только при закрытой крышке) → DarkWake.
  - Постоянно: `caffeinate -s -w <pid>` (на батарее по man не действует) — clamshell-сон превращается в DarkWake; сторож: на батарее убить удержание дисплея; ресинк слотов каждые 5 мин и при разрыве цикла >5 с (после сна).
  - Диагностика: пишет ВЕСЬ эфир ресивера в лог (`[эфир]`, hex) — оставлено намеренно.
- **mini, `~/bin/kvm-mouse-helper.sh`** (НЕ launchd! запускается вручную из терминала/Claude): читает `/tmp/kvm-mouse.fifo` («0» = мышь на макбук), зовёт нативный `~/bin/kvmmouse-bin`. Причина существования — TCC (см. ниже).
- Логи: `/tmp/kvm-follow.log`, `/tmp/kvm-mb.log`, `/tmp/kvm-mouse-push.log`. Ротация у агента макбука на 5 МБ.

## Твёрдо установленные факты о железе (не переоткрывать!)

1. **LG 0xF4**: вход переключается ТОЛЬКО проприетарным регистром 0xF4 на адрес 0x50 (`m1ddc set input-alt`, нужна HEAD-сборка). VCP 0x60 не работает (все коды — лишь мерцание). Код возврата m1ddc **всегда 0**, чтения яркости — статистика (норма ~7-9 из 10 верных).
2. **0xF4 нечитаем**: ответ — константное эхо `01 f4 49` на обоих входах (чтение ответа только по адресу 0x50; патч m1ddc это показал). Датчика «какой вход показан» НЕТ. Слабый суррогат: задержка чтений (активный ~94 мс, фоновый ~111 мс) — не откалиброван.
3. **DDC деградирует под шквалом команд**: чтения превращаются в мусор/нули, записи молча игнорируются. Самолечится ~35–40 мин ТИШИНЫ. Глубокий клин снимается ТОЛЬКО выдёргиванием шнура питания монитора на 2–3 мин (кнопка = дежурный режим, скалер жив). Поэтому посылки дозируются, а не спамятся.
4. **Гонка гашения (главная мина)**: при переключении входа НА макбук его дисплей пропадает на 2.6–4.4 с (хотплаг LG); при закрытой крышке через ~5 с после гашения наступает clamshell-сон. Одна побудка при приходе клавиатуры проигрывает гонку (доказано 12:24: clamshell убил дисплей через 2 с после побудки — чёрный экран навсегда). `caffeinate -d` clamshell-гашение НЕ предотвращает и погасший экран НЕ зажигает. Лечение: ЦИКЛ свежих `caffeinate -u -t 5` (с `-t 1` не будит вообще).
5. **Гибернация**: если макбук потерял питание (например, обесточили монитор — его 5 Вт пропадают) и уснул, через ~часы уходит в standby: USB обесточен, **клавиатура его НЕ разбудит, сеть мертва — будит только крышка/кнопка**. После включения монитора при спящем макбуке **PD-контракт не восстанавливается сам** («No adapter attached») — нужно перевоткнуть USB-C-кабель (или MagSafe).
6. **TCC-сага (mini)**: vendor-интерфейс BLE-**мыши** требует `kTCCServiceBluetoothAlways` у процесса. У Terminal он есть → интерактивно работает; у launchd-процессов НЕТ и промпт им не показывается (испробовано ВСЁ: приложение-обёртка, нативный бинарь как главный исполняемый, встроенный `__info_plist` с NSBluetoothAlwaysUsageDescription, CBCentralManager с initWithDelegate+scan — система молчит; запись в TCC.db делать нельзя). Vendor-интерфейсы BLE-**клавиатуры** ещё строже (privilege violation ~ Input Monitoring) — **клавиатуру с mini программно не подвинуть вообще**. РЕШЕНИЕ: helper-процесс, запущенный из сессии с правами (права фиксируются при старте процесса и наследуются детьми) + fifo. После перезагрузки mini: `nohup ~/bin/kvm-mouse-helper.sh &` из терминала/Claude.
7. **Мышь в простое спит**: её BLE-радио засыпает, hid_enumerate на mini её не видит (>6 с ретраев мало), команда доходит при пробуждении (движение). Отсюда задержка следования ~8–10 с (событийный пуш падает, конвергентный — доносит). ChangeHost хосты 0-based: 0 = канал 1 (макбук), 1 = канал 2 (mini).
8. **Приход клавиатуры на Bolt сам будит макбук из DarkWake** (HID Activity) — дисплей зажигается в ту же секунду. Из ПОЛНОГО сна будит первое НАЖАТИЕ клавиши (0.4 с), не сам линк. Из гибернации — только крышка.
9. **Bolt pairing info (0xB5) не отдаёт** (err 0x02) — карта слотов только через fake arrival (0x41: тип в младшем    ниббле info-байта, 1=клава, 2=мышь; бит 0x40 = линка нет).
10. **macOS 26: скриптовый бандл через LaunchServices запускается под Rosetta** — нативному бинарю в бандле нужен `arch -arm64` в обёртке или Mach-O как главный исполняемый (и не ломать подпись: `codesign --force -s -` после любого cp).

## Ложные гипотезы (не наступать снова)

- ~~«DDC невозможен, только гашение сигнала»~~ (старая память) — 0xF4 работает.
- ~~«0xF4 гейтится настройкой Auto Input Switch»~~ — владелец подтвердил: настройка была включена, а вход всё равно не переключался. Настоящая причина была двойная: деградация DDC → потом спящий/гибернирующий макбук на тёмном входе.
- ~~«Кабели надо поменять местами»~~ (из хроники 14.08) — стоило вечера хаоса.
- ~~«Два DDC-мастера убили регистр»~~ — недоказано; но правило одного мастера ОСТАВЛЕНО (меньше команд — меньше деградации, нет гонок).
- ~~«Мышь не приехала»~~ — часто она приехала и вернулась конвергенцией, потому что агент считал клавиатуру отсутствующей, или просто опоздала на ~10 с. Смотреть лог, а не верить глазам.
- «Автопоиск входа спасёт от чёрного экрана» — автопоиск LG ленив (12–20 с из хроники v1) и на него полагаться нельзя.

## Известные слабости (кандидаты на поломку)

1. **Мышь догоняет до ~10 с**, если лежала без движения (BLE спит). Двинуть мышь — доедет мгновенно. Возможное улучшение: часто повторять пуш первые секунды после ухода клавиатуры.
2. **Болтанка мыши по каналам (в т.ч. мёртвый 3-й)** — наблюдалась владельцем при быстрых циклах; в дампе эфира поймать «второго командира» (подозрение: Logi Options+ на одной из машин шлёт свой ChangeHost поверх нашего). Дамп включён — при рецидиве смотреть `[эфир]` в /tmp/kvm-mb.log на момент болтанки (наши swid: 0x0D агент, 0x0E пуш mini; чужой swid = виновник).
3. **Перезагрузка mini** убивает helper → уход мыши на макбук перестаёт работать (возврат работает — он через ресивер). Симптом: в /tmp/kvm-mouse-push.log нет записей при переключениях. Лечение: `nohup ~/bin/kvm-mouse-helper.sh &` из терминала.
4. **Обесточивание монитора** → макбук теряет 5 Вт → на батарее → полный сон → гибернация. Симптом: чёрный экран при «1», SSH мёртв, mini пишет «[спасение] макбук молчит». Лечение: крышка → проверить питание (`pmset -g batt`), если «discharging» — перевоткнуть USB-C. Профилактика: MagSafe.
5. **DDC-клин монитора** от шквала команд (интенсивное тестирование!). Симптом: яркость-ридбэк врёт (мода не совпадает с записанной). Лечение: 40 мин тишины или шнур на 2–3 мин.
6. Однажды клавиатура вообще не ушла с mini по нажатию «1» (ни одного следа ни в одном логе) — аппаратный пропуск нажатия, софтом не лечится.
