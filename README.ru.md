# kvm-follow

Монитор следует за клавиатурой. Без KVM-коробки, без USB-свитча, без лазанья за стол.

*[English version](README.md)*

Два Мака делят один монитор и одну клавиатуру Logitech с Easy-Switch. Вы нажимаете
кнопку Easy-Switch, клавиатура уезжает на вторую машину — и монитор уезжает следом,
сам, примерно за секунду. Это вся функциональность.

```
2026-08-13 16:10:11 [leave]  monitor -> peer in 2s
2026-08-13 16:10:24 [return] monitor -> host in 1s
2026-08-13 16:10:49 [leave]  monitor -> peer in 1s
2026-08-13 16:11:01 [return] monitor -> host in 1s
```

Железо, на котором это собрано и проверено:

| | |
|---|---|
| Монитор | LG UltraWide 2560×1080 (семейство WQ), встроенного KVM нет |
| Хост | Mac mini M4 Pro на HDMI, работает постоянно |
| Пир | MacBook Pro M1 Pro на USB-C, крышка закрыта |
| Клавиатура | MX Keys Mini — на хост по Bluetooth, на пир через Bolt-ресивер |
| Мышь | MX Master 3S, та же пара Easy-Switch |

Всё завязано на Apple Silicon, потому что опирается на
[m1ddc](https://github.com/waydabber/m1ddc).

## Самое главное — то, на что ушло больше всего времени

Если читать только один раздел, читайте этот. Три факта, ни один из которых не описан
в очевидном месте.

**1. Новые мониторы LG игнорируют стандартный DDC-регистр входа.** VCP `0x60` — это
*тот самый* регистр выбора входа, и панель честно перечисляет в своих capabilities
коды 15/17/18. Каждый из них принимается и не делает ничего: экран мигает и остаётся
где был. Чтение `0x60` всегда возвращает `0` — баг прошивки, так что даже узнать
текущий вход программно нельзя.

**2. Настоящий регистр проприетарный: `0xF4`, отправленный на I2C-адрес `0x50` вместо
обычного `0x51`.** В m1ddc это команда `set input-alt`. Проверенные вживую коды:

| Вход | Код | Hex |
|---|---|---|
| HDMI 1 | 144 | `0x90` |
| HDMI 2 | 145 | `0x91` |
| DisplayPort 1 | 208 | `0xD0` |
| USB-C | **465** | **`0x1D1`** |

**3. Homebrew-сборка m1ddc не способна отправить этот код USB-C в принципе.** В релизе
1.2.0 команда `input-alt` есть, но реализация сломана: неверная контрольная сумма и
обнулённый старший байт значения. `0x01D1` обрезается до `0xD1` — то есть команда,
переключающая монитор на ноутбук, не «работает через раз», её невозможно выразить.
Нужна сборка из HEAD (исправление приехало в
[PR #52](https://github.com/waydabber/m1ddc/pull/52), апрель 2025). Именно эта деталь
съедает вечер, если её не знать: всё *выглядит* правильно, утилита возвращает 0,
и ничего не происходит.

И свойство, благодаря которому вся схема вообще возможна:

**DDC-регистры глобальны для монитора, а не привязаны к активному входу.** Любая
машина может отправить команду переключения в любой момент, независимо от того, её
картинка сейчас на экране или нет. Поэтому уходящая машина может сама сказать монитору
«уходи», а возвращающаяся — попросить его обратно. Никакого рукопожатия и общего
состояния не требуется.

## Как это устроено

На хосте крутится маленький цикл опроса. Раз в 0,3 с он спрашивает
`blueutil --is-connected "MX Keys Mini"`:

- **Клавиатура пропала** → SSH на пир, разбудить его, затем отправить `input-alt 465`.
  Монитор уходит на USB-C, пир уже проснулся, черноты нет.
- **Клавиатура вернулась** → отправить `input-alt 144` локально *и* с пира. Подстраховка:
  после того как монитор какое-то время стоял на другом входе, DDC-канал хоста иногда
  глохнет, и проходит именно копия команды, посланная с пира.

Три неочевидные детали, которые важны:

- **Детектировать клавиатуру может только хост.** `blueutil --is-connected` работает по
  *имени* устройства; при передаче MAC-адреса он возвращает `0` даже для подключённого
  устройства. На пире клавиатура приходит через Bolt-ресивер, а тот держит три
  HID-интерфейса открытыми постоянно — `ioreg` и `hidutil` не меняются, наблюдать
  нечего. Отсюда односторонняя схема: хост решает, пир подчиняется по SSH.
- **Пир нужно будить до переключения, а не после.** `caffeinate -u -t 5` будит,
  `caffeinate -u -t 1` не будит вообще. Дальше `caffeinate -d` удерживает дисплей,
  потому что `powerd` иначе отпускает его через **30 секунд**.
- **Каждую DDC-команду слать дважды.** Панели LG глотают первую достаточно часто,
  чтобы это раздражало, а вторая стоит 150 мс.

## Что нужно

На обеих машинах:

- Apple Silicon (в m1ddc нет поддержки Intel)
- [m1ddc](https://github.com/waydabber/m1ddc), собранный из HEAD — см. ниже
- Homebrew

Только на хосте:

- `blueutil` — `brew install blueutil`
- SSH-доступ к пиру по ключу

Только на пире:

- Включён удалённый вход (Системные настройки → Основные → Общий доступ → Удалённый вход)

Клавиатура Logitech с Easy-Switch, привязанная к хосту по Bluetooth и к пиру любым
способом. Подойдёт любая клавиатура, у которой при смене канала реально рвётся
Bluetooth-соединение.

## Установка

### 1. m1ddc из HEAD, на обеих машинах

```sh
brew uninstall m1ddc            # если стоит релиз — он не подойдёт
git clone https://github.com/waydabber/m1ddc
cd m1ddc && make
sudo cp m1ddc /opt/homebrew/bin/m1ddc
```

Если `make` падает на отсутствующих заголовках SDK — у вас слишком старые Command Line
Tools (`xcode-select --install`). Совершенно нормально собрать бинарник на одной машине
и скопировать на другую: это один исполняемый файл, обе машины arm64.

Проверить, что исправленный `input-alt` на месте:

```sh
m1ddc set input-alt 465 && echo "если монитор переключился — всё готово"
```

### 2. SSH с хоста на пир

```sh
ssh-keygen -t ed25519 -f ~/.ssh/kvm_peer -N ''
ssh-copy-id -i ~/.ssh/kvm_peer.pub youruser@peer.local
ssh -i ~/.ssh/kvm_peer youruser@peer.local true && echo ok
```

### 3. Агент, на хосте

```sh
git clone https://github.com/xscanlordx-code/kvm-follow
cd kvm-follow
./install.sh
$EDITOR ~/.config/kvm-follow/config     # имя клавиатуры, коды входов, адрес пира
launchctl kickstart -k gui/$(id -u)/com.kvm.follow
tail -f /tmp/kvm-follow.log
```

### Как найти коды входов для своего монитора

Коды выше — от конкретного LG UltraWide. Если панель другая:

```sh
./tools/probe-inputs.sh          # перебирает типовые коды с паузой 5 с
./tools/probe-inputs.sh 144 465  # или конкретные
```

Запускайте с той машины, которая останется с картинкой, и помните, что DDC глобален:
если экран потерялся, код возврата можно послать со второй машины.

## Компромисс, о котором надо знать

Пробуждение пира занимает около 1,5 с, поэтому скрипт не снимает своё удержание
`caffeinate` при переключении обратно — пир остаётся бодрым, и следующее переключение
мгновенное. Цена: пока агент работает, пир сам не засыпает.

Параметр `WAKE_HOLD` это ограничивает: по умолчанию 1800 с, то есть удержание истекает
через полчаса после последнего переключения, и унесённый со стола ноутбук засыпает
нормально. `WAKE_HOLD=0` — бессрочное удержание (быстрее всего, но пир не заснёт до
перезагрузки).

Это касается только засыпания дисплея и системного сна по бездействию. Ноутбук,
настроенный засыпать при закрытии крышки, при закрытии крышки всё равно заснёт.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Ничего не происходит, код возврата 0 | Релизная сборка m1ddc. Проверьте `input-alt` на двухбайтовом коде. |
| Монитор мигает, но не переключается | Вы шлёте `set input`, а нужно `set input-alt`. |
| Чёрный экран после переключения на пир | Пир спал, а SSH не прошёл — смотрите `/tmp/kvm-follow.log`. |
| Переключение срабатывает дважды или скачет | Увеличьте `SETTLE`, Bluetooth-стек дребезжит. |
| `blueutil --is-connected` всегда 0 | Передан MAC-адрес. Нужно имя устройства. |
| Работает только в одну сторону | У хоста заглох DDC-канал; ровно поэтому обратный путь дублируется с пира. |
| Агент умирает при загрузке | Неверные пути к `blueutil`/`m1ddc` в конфиге, смотрите `/tmp/kvm-follow.err`. |

## Тупики, чтобы вы их не повторяли

- **Переключение через снятие видеосигнала** (`pmset displaysleepnow` плюс автопоиск
  живого входа самим монитором). Это *работает*, и это была первая версия здесь, но
  занимает 12–20 с на переключение и даёт гонки HPD, из-за которых macOS перекладывает
  окна. DDC-путь в десять раз быстрее и вообще не трогает видеолинк.
- **LG OnScreen Control / LG Dual Controller** — смены входа нет. Dual Controller
  перегоняет между машинами *курсор* по сети, это другая функция.
- **MonitorControl** — только яркость и звук, переключение входов не реализовано.
- **ddcctl** — только Intel.
- **Встроенный KVM монитора** — у этой панели его нет. У тех, где он есть, он обычно
  живёт на `0xE7`/`0xE8`, и в m1ddc для Dell и ASUS есть отдельные команды.
- **Детект клавиатуры на стороне ноутбука** — невозможен через Bolt-ресивер, см. выше.
